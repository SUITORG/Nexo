🚑 Plan de Desarrollo: App de Ambulancias "MediRápido"
FASE 1: PLAN ESTRATÉGICO Y ARQUITECTURA BÁSICA
1. VISIÓN GENERAL DEL PROYECTO
Nombre sugerido: MediRápido (branding configurable)
Concepto: Plataforma que conecta pacientes/usuarios con ambulancias privadas de forma inmediata, similar a Uber pero optimizado para emergencias médicas y traslados programados.
Diferencias clave vs. Uber:
El usuario NO es un "pasajero normal": puede estar inconsciente, acompañado por familiares, o necesitar atención médica durante el traslado
Se requiere información médica básica (alergias, tipo de sangre, contacto de emergencia)
Las ambulancias tienen equipamiento médico variable (básica, avanzada, UCI móvil)
El "conductor" es un paramédico o técnico en urgencias
Se necesita integración con hospitales/centros médicos
2. STACK TECNÓLÓGICO RECOMENDADO (Principiante-friendly)
Hojas
Capa	Tecnología	¿Por qué?
Frontend (App móvil)	Flutter o React Native	Un solo código para iOS y Android. Flutter es más amigable para principiantes
Frontend (Web admin)	React.js o Vue.js	Muy documentado, muchos tutoriales
Backend	Firebase (Google) o Supabase	No necesitas servidor propio inicialmente, base de datos + autenticación + hosting incluidos
Base de Datos	Cloud Firestore (Firebase) o PostgreSQL (Supabase)	Escalable, gratis para empezar
Mapas/Geolocalización	Google Maps API	Estándar de la industria
Notificaciones Push	Firebase Cloud Messaging (FCM)	Gratis y confiable
Pagos	Stripe o MercadoPago	Fácil integración, documentación en español
Almacenamiento	Firebase Storage	Para fotos de perfil, documentos médicos
💡 Recomendación para principiantes: Empieza con Flutter + Firebase. Es el combo más documentado, tiene muchos tutoriales en YouTube, y la curva de aprendizaje es suave.

6. SEGURIDAD (Fase crítica - NO negociable)
🔒 Seguridad de Datos (HIPAA / Ley de Protección de Datos)
Hojas
Aspecto	Implementación
Cifrado en tránsito	HTTPS/TLS 1.3 para todas las comunicaciones
Cifrado en reposo	Datos médicos cifrados en la base de datos
Autenticación	Firebase Auth con verificación de teléfono + reCAPTCHA
Reglas de seguridad	Firestore Rules: cada usuario solo ve sus propios datos
Datos médicos sensibles	No almacenar historial clínico completo. Solo: tipo de sangre, alergias, contacto de emergencia
Consentimiento	Pantalla de términos y condiciones + política de privacidad obligatoria
Borrado de datos	Función para que el usuario pueda eliminar su cuenta y datos (GDPR/LGPD)
🛡️ Seguridad Operativa
Hojas
Aspecto	Implementación
Verificación de conductores	Documento de identidad, licencia de conducción, certificación de paramédico, antecedentes penales
Rastreo en tiempo real	Ubicación GPS compartida con contacto de emergencia durante el traslado
Botón de pánico	Usuario y conductor pueden activar alerta a central de monitoreo
Registro de viajes	Cada servicio queda registrado con: hora, ruta, conductor, paciente, costo
Límites de acceso	Solo usuarios verificados pueden solicitar servicios

Flujo de pago:
Usuario guarda tarjeta de forma segura (tokenizada - no guardas el número real)
Al finalizar el servicio, se cobra automáticamente

El conductor recibe su comisión en su cuenta bancaria (semanal)
