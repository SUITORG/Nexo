# Campañas AI - Proyecto CMS

## Contexto del proyecto
CMS de generación de campañas publicitarias con IA: pipeline Brief → MediaPlanner → BriefMarker → VIDE que produce videos publicitarios (guion, voz, imágenes, overlays) a partir de datos de empresas en Google Sheets + Supabase. Stack: Node.js (server propio, puerto 8000), FFmpeg, OpenRouter/Gemini (+ Ollama local como fallback), Edge TTS, Supabase.

## Alcance
Proyecto local — no se despliega vía GitHub Pages. El SEO/deploy de `grupoevasol.com` es un proyecto aparte en la raíz de `SuitOrg` (ver `SuitOrg/CLAUDE.md`), no vive aquí.

## Comandos clave
- `npm start` — arranca el servidor (`local-server-node.js`, puerto 8000)
- `npm run mock` — servidor mock (`mock-server.js`)
- `node scripts/seed-supabase.js` — siembra tablas `recetas`/`tendencias` en Supabase
- `npm test` — placeholder; la prueba real es manual abriendo `test.html` en navegador

## Reglas y convenciones
- Voz: Edge TTS neuronal — no gTTS, no versión npm no-comercial.
- IA: OpenRouter/Gemini como primario, Ollama local como 3er fallback.
- El estilo visual de un video se fija en la 1ra aprobación del plan y no cambia en reintentos.
- Overlays de logo/avatar/contacto van como miniaturas sobrepuestas sobre las imágenes generadas por IA, nunca como slides separados.
- Campos autollenados desde Google Sheets: normalizar/tolerar variaciones de formato (mayúsculas, protocolo de URL, etc.), nunca blanquear silenciosamente por un chequeo estricto.
- `SuitCampanas/` no pasa por el pipeline de deploy de GitHub Pages del repo raíz.
- Búsqueda de tendencias: hay dos flujos distintos, no confundirlos. BDSMT/VIDE (`buscarTendencias()` en `script.js`) es manual — el usuario elige una de la lista antes de que se aplique a `#aiTheme`. El Agente de Tendencias de modo IMG (`scripts/agent-tendencias.js`) es automático — procesa las 5 sin selección.

## Decisiones tomadas
- Selector de alcance de producción: Completo (12) / Semanal (7) / Demo (4), idempotente.
- `index.html` VIDE reorganizado en 3 bloques: suelto / campaña / retomar.
- Retomado (antes pausado) — conversión de guion narrativo (meditación, voz en off larga) a video: VIDE ahora genera TTS **por escena** (no un solo pase con todo el guion), con silencio real (no frame negro) entre segmentos. El guion de texto libre (`#videGuion`, sin JSON) reconoce automáticamente el formato con `[PAUSA DE SILENCIO: N SEGUNDOS]`, `[MÚSICA:]`, `[EFECTO:]`, encabezados `Sección (N minutos)` y un bloque final `Prompts para Fotografía...` (`parseGuionNarrativo()` en `local-server-node.js`). Selector de ritmo de voz (`--rate` de Edge TTS) agregado en la UI (Normal/Lento/Muy lento).
- SFX real en VIDE (antes se parseaba `scene.sfx` y se descartaba, nunca sonaba — ver B18): tipos fijos (whoosh/glitch/pop/bassdrop) vía `sfx.py` igual que ViRe, y sonido ambiental real (cuencos, olas, campanas...) para `[EFECTO: ...]` vía API de Freesound (`FREESOUND_API_KEY` en `.env`), filtrado a licencia CC0. Requiere traducir la consulta a 1-2 sustantivos en inglés antes de buscar (Freesound es Y-lógico y está en inglés — `traducirSfxQuery()`), verificado en vivo contra la API real.
- Estilos visuales con "nombre fijo, color como única variante": `video_subestilos.parametros_visuales.template` selecciona un componente Remotion alternativo (`SceneRenderer.tsx` en `SuitVidGenRemotion`) que dibuja tipografía/layout/decoración fijos y lee `scene.brand_colors` (background/ink/accent, extraídos del logo o ajustados a mano) para el color exacto — la foto de fondo IA solo puede *acercarse* al color vía texto en el prompt. Implementado: `paper` (Papel & Marcador, Editorial), `pinterest_ad` (Pinterest Ganancia Viral, Promo Comercial), `ranking_tarjetas`, `diario_ilustrado`, `cosmic_listicle_dorado` y `pizarra_minimalista` (estos últimos 4 son "📊 Infografías & Listas" — todos con `content_shape: "lista"` + `item_count` salvo `diario_ilustrado`, que es título+cuerpo+chips de pasos, no lista de tarjetas; ver bullet de items abajo). Los templates Remotion (look real, color exacto) solo aplican en ViRe — VIDE (FFmpeg) tiene un nudge cosmético (`VISUAL_STYLE_FONTS`/`getFontForVisualStyle`: fuente bold instalada en Windows que se acerca al template) pero nunca dibuja tarjetas/grid — es una limitación de motor, no un bug.
- Contenido tipo lista/ranking (`items[]`, para estilos con `content_shape: "lista"` como Ranking en Tarjetas) propagado en TODO el pipeline, no solo en "Solo Imagen": `construirPromptGuion()` (script.js) recibe `contentShape`/`itemCount` y, cuando aplica, exige al JSON generado 1 sola escena con `duracion` = el video completo + un array `items` de N tarjetas investigadas sobre el Brief real (no genéricas) — verificado en vivo con Brief real de Noe Thermomix. `parseGuionScenes()` (server) preserva `items` en ambas ramas JSON (array/`escenas`), y `/api/vire-produce` lo reenvía a cada escena de ViRe — verificado renderizando el JSON generado end-to-end (mismo componente `RankingTarjetasScene`). Antes solo `/api/vire-still` (Solo Imagen sin guion) sabía generar `items`; el flujo de video completo/JSON los ignoraba en silencio (tarjetas vacías).

- Bug corregido: "🤖 Generar JSON" (VIDE) fallaba con "La IA no devolvió JSON válido" cuando el modelo (`deepseek/deepseek-v4-flash`) daba 429/error — causa real: `/api/ai/generate` armaba su respaldo como `[requestModel, "deepseek/deepseek-v4-flash"]`, y como el cliente YA pide ese mismo modelo, el dedup dejaba **un solo modelo real** en la lista — sin margen, caía directo a Ollama local (modelo débil, JSON roto en prompts largos). Se intentó primero agregar `"openrouter/free"` como segundo modelo (mismo patrón que ya tenía `callAIJson()`), pero **verificado en vivo que está roto**: `openrouter/free` mapea a `auto/best-free` en OmniRoute, que enruta a una cuenta Augment Code con cupo agotado y responde HTTP 200 con un mensaje de texto ("has run out of usage...") en vez de un error real — se cuela como "respuesta válida" y revienta el `JSON.parse()` del lado del cliente, el MISMO síntoma reportado, solo disfrazado. Además, esa ruta puede tardar 2-3 minutos en fallar internamente ("Maximum combo retry limit reached") antes de ceder el paso al siguiente fallback. Fix real aplicado en `/api/ai/generate` Y `callAIJson()` (que tenía el mismo defecto latente, nunca antes reportado): en vez de un "segundo modelo" que no existe de forma confiable hoy, se reintenta el MISMO modelo hasta 2 veces con espera de 5s cuando el error es 429/rate-limit (transitorio, casi siempre se resuelve solo esperando), y se corta de inmediato en errores no-transitorios (ej. "Model is unavailable"). De paso, `callOpenRouter()` ahora adjunta `error.status` al error lanzado (detección de 429 ya no depende de que el texto del proveedor incluya la palabra "429") y tiene un timeout explícito de 25s en el fetch a OmniRoute (antes sin límite — lo que permitía el cuelgue de minutos de `auto/best-free`). Verificado en vivo: confirmado el bug de `openrouter/free` reproduciéndolo en tiempo real, confirmada la corrección con una respuesta real (no basura) en ~56s cuando deepseek falló y cayó a LM Studio, y 4 casos aislados de la lógica de reintentos (éxito directo, 429→éxito, 429 agotado, error no-transitorio corta inmediato).

- 3 bugs reales encontrados generando un video de extremo a extremo con IA real (no un guion a mano) para los 3 templates nuevos — ninguno se había visto antes porque las verificaciones previas de estos templates usaban guiones escritos a mano con todos los campos "bien puestos":
  1. **Guion "lista" sin `items`**: `construirPromptGuion()` exige `items` cuando `contentShape === 'lista'`, pero un modelo de respaldo débil (Ollama local, usado cuando `oc/deepseek-v4-flash-free` está caído — pasó real en vivo, "Model is unavailable" repetido) devuelve JSON válido y completo salvo por `items`, y nada lo detectaba: el template renderizaba el fondo vacío, sin ninguna tarjeta. Mismo fallback de 3 niveles aplicado a las 3.
  3. **Ícono por-tarjeta como texto roto**: el prompt pide "un emoji relacionado" para `item.icono` (que se dibuja como texto plano, sin pasar por Iconify — a propósito, ver arriba), pero en vivo el modelo a veces escribe la palabra en vez del glifo (`"checkmark"`, `"cancel"`, `":star:"`) y eso se veía literal en pantalla. De paso, `PizarraMinimalistaScene`'s `pastelIndexFor()` (color mint/coral por fila según ✓/✗, ver bullet de arriba) se amplió de comparación exacta a `.includes()` para reconocer también estas palabras (`"checkmark"`→mint, `"cancel"`→coral), no solo el glifo o "check"/"x"/"cross" literales.
