# ADR-011: Ponytail Ladder Skill

## Status
Accepted (2026-07-28)

## Context
Needed a way to reduce token waste from over-engineered code generated by AI agents.
External plugin `DietrichGebert/ponytail` (91k stars) provides this via hooks + skills,
but creates a dependency on an external repo and only covers ~80% of sessions' needs.

## Decision
Create an internal SuitOS skill `ponytail-ladder` that embeds the same decision ladder
directly into SuitOS workflows:

1. YAGNI — skip if not needed
2. Already in codebase — reuse
3. Stdlib — use it
4. Native platform feature — use it
5. Installed dependency — use it
6. One line — write one line
7. Minimum viable — smallest thing that works

Registered in `registry/skills.yaml`, referenced by `workflows/feature.yaml` and
`workflows/bugfix.yaml`, and validated by a new `overengineering` check in
`reviewer/profiles.yaml` (standard profile).

## Rationale
- ~50 lines of YAML vs depending on an external npm package
- Covers ~80% of Ponytail's value (the ladder itself) with zero external deps
- The remaining 20% (dynamic levels, `/ponytail-review` command, auto-subagent injection)
  is rarely used and can be added later if needed
- SuitOS loader loads the skill automatically when the workflow requires it
- Works with both OpenCode and Claude Code since both read `.suit/`

## Consequences
- Agents will produce smaller, more focused code by default
- Reviewer catches over-engineering as a warning
- No dependency on external plugin; the external Ponytail can still be used alongside
- Does NOT provide: dynamic intensity levels (lite/full/ultra/off), interactive slash
  commands (`/ponytail-review`, `/ponytail-debt`), or automatic subagent injection
